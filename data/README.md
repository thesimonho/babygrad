# Datasets

Small CSV datasets for early forward-only network experiments.

## `iris.csv`

Classic Iris flower classification dataset.

- Rows: 150 examples
- Inputs: `sepal_length_cm`, `sepal_width_cm`, `petal_length_cm`, `petal_width_cm`
- Target: `species`
- Classes: `Iris-setosa`, `Iris-versicolor`, `Iris-virginica`
- Source: UCI Machine Learning Repository Iris data file
  (`https://archive.ics.uci.edu/ml/machine-learning-databases/iris/iris.data`)

## `concentric_circles.csv`

Synthetic two-class dataset for the Phase 7 residual-network demo. One class is
an inner disk, the other an outer ring, separated by an empty margin. No linear
boundary can separate them, and recovering the boundary requires composing a
radius-like feature (`x1**2 + x2**2`) from the raw inputs — so a shallow network
underfits and a deep *plain* stack struggles to train, while a deep residual
network learns it cleanly.

- Rows: 5000 balanced examples (2500 inner, 2500 outer)
- Inputs: `x1`, `x2`
- Target: `label` (`inner`, `outer`)
- Generated by: `python data/generate_concentric_circles.py`

The generator is deterministic (fixed seed). Radii are area-weighted so points
spread evenly across each ring, with small Gaussian jitter on each coordinate.
Used by `notebooks/phase7_residual_networks.ipynb`, which trains on a slice of
the rows to keep the pure-Python run to a couple of minutes.

## `number_words.csv`

Synthetic sequence-to-sequence dataset for the Phase 8 transformer demo. Each
row pairs an English spelling with its digit form (`three hundred forty two` →
`342`).

- Rows: 1200 examples
- Source: `words` (1–9 words)
- Target: `digits` (1–6 characters)
- Generated by: `python data/generate_number_words.py`

Numbers are **balanced across digit lengths** (10 / 90 / 275 / 275 / 275 / 275
for 1–6 digits) rather than drawn uniformly from the range. A uniform draw would
make ~88% of rows six digits long and omit one- and two-digit numbers entirely,
so the model would only ever see one shape of problem. Balancing exposes the
full compositional range and lets accuracy be reported per digit length, which
is where a partly-learned place-value rule shows itself. The one- and two-digit
buckets are exhaustive — only 10 and 90 such numbers exist — so their unused
share flows to the longer lengths.

Every number appears at most once, so any train/val/test split of the file is
automatically disjoint. That matters because the split is what measures whether
the model learned place value or merely memorised the rows it trained on — the
point of choosing a compositional task over a lookup-shaped one. The spelled
form also gives the tokenizer real subword structure (`-teen`, `-ty`, and the
recurring `hundred`/`thousand`).

The generator is deterministic (fixed seed) and takes `--pairs`, `--max-digits`,
and `--seed`, so a dev iteration can shrink the dataset without editing the
script. Splitting is left to `split_train_val_test`.

## `magic_gamma_telescope.csv`

Binary classification from the MAGIC Cherenkov telescope. Monte-Carlo-simulated
particle showers described by their "image" ellipse (Hillas parameters); the
task is to separate gamma-ray signal from hadronic cosmic-ray background. Larger
and genuinely harder than iris — the classes overlap, so hyperparameters visibly
affect the validation curve instead of everything converging to the ceiling.

- Rows: 19020 examples (12332 gamma `g`, 6688 hadron `h`)
- Inputs: `fLength`, `fWidth`, `fSize`, `fConc`, `fConc1`, `fAsym`, `fM3Long`,
  `fM3Trans`, `fAlpha`, `fDist` (all continuous Hillas parameters)
- Target: `class` (`g` = gamma / signal, `h` = hadron / background)
- Source: UCI Machine Learning Repository MAGIC Gamma Telescope data file
  (`https://archive.ics.uci.edu/ml/machine-learning-databases/magic/magic04.data`),
  with a header row added to match the other CSVs.

Note the ~65/35 class imbalance: a model that always predicts `g` scores ~65%
accuracy, so watch per-class performance, not just overall accuracy.
